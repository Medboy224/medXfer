# medXfer — the app (Flutter)

The interface of medXfer for Android, Windows and Linux (milestone J6b, plan:
[../docs/medxfer-plan-j6b.md](../docs/medxfer-plan-j6b.md)). The core is the Go library of
`cmd/libmedxfer`, loaded in the app's own process through `dart:ffi` (bible §10.4).

## Layout

- `lib/core/`: the core as the interface sees it (`core.dart`), the real adapter over the C
  library (`ffi_core.dart`), and a fake one that replays the golden scenarios of `xfer ctl`
  (`fake_core.dart`, DEV-17).
- `lib/platform/`: what the system does (folders; later the access point, the file picker,
  the background service), one interface per subject, one adapter per library.
- `lib/features/`: one folder per screen.
- `lib/l10n/`: French and English texts (`*.arb`); the Dart files are generated by
  `flutter pub get`.

## Building

From the repository root:

```sh
# Windows (PowerShell): the core for Windows and Android, then the app.
scripts\build-lib.ps1
scripts\stage-app-native.ps1
cd app; flutter build windows --release     # Windows: Developer Mode must be on (plugins)
cd app; flutter build apk --release         # Android

# Linux
bash scripts/build-lib.sh && bash scripts/stage-app-native.sh
cd app && flutter build linux --release
```

`stage-app-native` copies the libraries from `build/lib` to `app/native` (not in git), where
Gradle (`jniLibs`) and the CMake of the Windows and Linux runners take them.

## Tests

```sh
cd app
flutter analyze
flutter test        # the fake core; and the real one when build/lib holds the library
```
